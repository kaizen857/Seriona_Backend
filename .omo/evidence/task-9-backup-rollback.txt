Behavior implemented:
- V2->V3 migration now creates `<database>.bak` before destructive work.
- If migration throws after backup creation, the V3 cache closes SQLite, restores the main database from `<database>.bak`, reopens/configures SQLite, then rethrows.
- `SQLiteCacheV3::rollbackToBackup()` is available inside the V3 cache boundary and restores the main database from `<database>.bak`.
- Successful migration intentionally retains `<database>.bak`; this preserves a manual rollback source for task-10 integration/docs.

Focused coverage:
- Backup file is created before migration and contains `PRAGMA user_version=2`.
- Failed migration restores the main database to V2 state from backup.
- Manual rollback restores a successfully migrated V3 database back to the backup's V2 state.
- Backup creation failure prevents migration from starting and leaves the main DB at V2.
