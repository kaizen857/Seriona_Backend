Current-state finding:
- `SQLiteScannerCache` is still V2-shaped. It owns `roots`, `directories`, `songs`, `errors`, and sets `PRAGMA user_version=2` in `createSchema()` / `migrate()`.
- `schema_v3.sql` is a separate asset with `content`, `locations`, `lyrics`, `scan_roots`, `scan_errors`, `PRAGMA user_version=3`.
- This task intentionally did not change product code.

Planned method-to-SQL mapping for later CRUD work:
1. content
   - insert/upsert: `content_id` keyed row, update title/artist/album/album_artist/genre/track_number/disc_number/year/duration_ms/sample_rate/bit_depth/channels/play_count/rating/last_played_ms/created_at_ms/updated_at_ms
   - load: select content row by `content_id`
2. locations
   - insert/upsert: `location_id` keyed row, link `content_id` + `root_path`, store file path, file size, mtime, source path, cue offset, artwork, lyrics source, external LRC path/mtime, discovered/scanned timestamps
   - prune/delete: remove stale locations for a root or content relation
3. lyrics
   - replace-by-kind: delete existing rows for a location and `kind`, then insert ordered lines by `line_index`
   - load: select by `location_id` and `kind`, ordered by `line_index`
4. scan_roots
   - upsert root row with `directory_tree_hash`, `total_files`, `last_scan_mode`, `last_scan_duration_ms`, `last_scan_at_ms`
   - load/prune: fetch by `root_path`, remove oldest roots when over policy
5. scan_errors
   - replace-by-root: delete old rows by `root_path`, then insert ordered errors with `error_code`, `error_message`, `occurred_at_ms`, optional `file_path`

Task split to reduce file-conflict risk:
- Task 5: CRUD for `content` and `locations`
- Task 6: CRUD for `lyrics` and `scan_roots`
- Task 7: CRUD for `scan_errors` plus maintenance/load-path integration

Likely pitfalls from current V2 implementation:
- V2 caches preserve `play_count`, `rating`, and `last_played_ms` during refresh; V3 must preserve the same user-data rule across `content`/`locations` separation.
- V2 uses `track_id` as the song identity, so moving to dual IDs requires care around file moves and duplicate content.
- V2 `saveRoot()` currently deletes absent songs after upserting retained ones; V3 CRUD should preserve that replacement behavior without breaking shared content rows.
- V2 lyrics are split into embedded vs external rows; `lyrics` in V3 must keep ordering and source distinction.
