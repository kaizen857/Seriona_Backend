Implementation notes
- Existing `hashDirectoryMerkle()` was inspected first. Its prior private recursion mixed directory entries with file content hashes, file size, and mtime, so it was not a safe Phase 3 structure-only boundary.
- New `computeDirectoryTreeHash(rootPath)` returns the existing `DirectoryHashResult` and `HashError` shape from `hash_utils.h`, preserving scanner-local error contracts without changing public scanner service contracts.
- The implementation hashes only relative path names, entry kind, directory topology, and child directory sub-hashes. It does not open or read file contents and does not include file size or mtime.
- Old `hashDirectoryMerkle()` now delegates to `computeDirectoryTreeHash()` so scanner code has one directory-tree hash behavior rather than two incompatible algorithms.
- Missing roots return no hash plus `HashErrorCode::IoFailure` / `ScannerErrorCode::RootUnavailable`, matching existing hash error style.

Focused coverage
- `scanner directory tree hash describes structure without reading file content`: proves repeated stable 32-byte hex hash, file-content-only rewrite does not change the hash, add changes the hash, rename changes the hash, delete changes the hash.
- `scanner directory tree hash reports missing roots without partial hash`: proves malformed missing-root input returns deterministic error and no partial hash.
- Existing `scanner directory merkle hash is stable and changes on child add delete and rename` now characterizes the compatibility wrapper because `hashDirectoryMerkle()` delegates to the new entrypoint.
