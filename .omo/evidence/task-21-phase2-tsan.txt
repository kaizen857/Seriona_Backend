Stress / integration description:
- Added CTest target `seriona.scanner.phase2_tsan_stress`.
- The test creates 1000 deterministic audio fixture paths under `TempScannerRoot`.
- Each run constructs `ScannerWorkerPool::Config{.workerCount = 4, .tagReaderSlots = 4}`.
- It repeats the 1000-task batch 10 times, for 10000 total TagReader seam calls.
- A condition-variable probe blocks the first four entries per batch until all four workers have entered, proving the 4-worker concurrent path without wall-clock thresholds.
- Assertions cover result count, empty worker-pool errors, submitted/scanned stats, stable result paths, metadata paths/titles, and non-empty content hashes.

Initial TSAN finding and fix:
- First `ctest --test-dir build-tsan -R 'seriona.scanner' --output-on-failure` found `WARNING: ThreadSanitizer` in `seriona_scanner_service_tests`.
- TSAN reported a data race in `OrchestratedFileScannerService::scanWorkerLoop()` reading `scanWorkerStopping_` while construction initialized the same object.
- Root cause: member declaration order started `scanWorker_` before `scanWorkerStopping_` was initialized.
- Fix: move `scanWorkerStopping_` before `scanWorker_` in `src/scanner/file_scanner_orchestrator.cpp` so the worker wait predicate reads an already-initialized flag.
- A second TSAN run had no TSAN warnings but exposed a sanitizer-only timing false negative in `scanner service cache lookup reuses a high-count cached root`; `waitForSnapshot()` allowed only about 100ms while TSAN needed about 356ms for the 96-song first scan. The test wait budget is now about 2s, still based on observable state and not a pass/fail performance threshold.
