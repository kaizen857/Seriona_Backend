Implementation notes:
- Added `CachedSongPathIndex = std::unordered_map<std::string, std::reference_wrapper<const cache::CachedSong>>` in the orchestrator anonymous namespace.
- `reconcileRoot()` now builds the path index once on the main scan thread immediately after `cache.loadRoot(rootPath)`.
- Index keys use existing `pathKey()` normalization, matching the previous `cachedSongByPath()` comparison behavior.
- `buildCachedSongPathIndex()` uses `try_emplace()`, so duplicate normalized paths preserve the previous `std::ranges::find_if()` first-match behavior.
- `prepareAudioTask()` and `reconcileLyrics()` now receive the read-only index and use `cachedSongByPath(cachedSongsByPath, path)`, which performs `unordered_map::find()`.
- Worker threads do not mutate or own the index. Workers only receive `AudioReconcileTask` values already populated on the main thread and the existing synchronized `WorkerSongStore` for full song handoff.
- Task 19 ordering is preserved: the `std::stable_sort(workerResults.begin(), workerResults.end(), discoveryIndexForWorkerResult...)` block was left intact.
- No Phase 3 incremental scanning behavior, public scanner API, dependencies, or worker-pool semantics were changed.

Focused coverage:

- Added exact CTest alias `seriona.scanner.cache_lookup` in `tests/CMakeLists.txt`.
- The test creates 96 audio fixtures, runs an initial full scan, then re-scans the high-count cached root. It asserts TagReader read count stays at 96 on the second scan and that the tail entry (`track-95.flac`) restores external lyrics from cache.
