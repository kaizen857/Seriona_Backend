Implementation notes
- `reconcileRoot()` now receives the `ScanModeDecision` selected in `runScan()`.
- Full mode keeps the existing all-candidate worker/cache path.
- Incremental mode loads V3 sidecar locations from `<scanner-cache>.scan-roots-v3.sqlite`, calls `planIncrementalScan()`, calls `pruneDeletedLocations()`, reuses unchanged V2 cached songs directly, and submits worker tasks only for added/changed paths.
- Successful unchanged + worker songs are merged by original discovery index before lyrics reconciliation, cache save, `FileScanned`, and playlist aggregation.
- The task-23 sidecar bridge now upserts V3 scan root, content, and location rows for successful published songs, then prunes sidecar locations to retained IDs. This is required because the active runtime cache is still V2.
- `cachedLocationFromSong()` now uses `computeLocationId(path, size, mtime)` so V3 location state matches `planIncrementalScan()` comparisons.
